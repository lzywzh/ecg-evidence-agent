# 心电报告术语与指南证据检索 Agent 设计

日期：2026-09-17  
状态：已由用户确认设计方向，等待书面规格复核  
项目定位：学习与求职演示，不是医疗器械，不提供诊断、治疗、用药或风险决策

## 1. 问题与目标

本项目面向公开或明确获准使用的心电指南、共识与术语资料，建立一条可复现的“资料导入—证据检索—来源回溯”链路，并在后续阶段加入报告字段提取、带引用回答和有限工具调用。

系统首先解决工程可核验性，而不是追求模型能力：每条证据必须能够回到具体来源和位置；报告中没有出现的字段不得补造；资料不足、来源冲突或问题超出资料范围时必须明确说明。

第一阶段只证明最小纵向链路，无需模型密钥。它导入合成资料、持久化来源和片段、执行确定性关键词检索，并通过 FastAPI 返回原文片段及来源。第一阶段不生成医学解释，因此不能将检索命中描述为医学结论。

## 2. 用户场景

完整项目覆盖三个核心场景：

1. 用户输入一个心电报告术语，系统返回与该术语相关的资料原文、发布机构、版本和位置。
2. 用户输入报告文字，系统仅提取文本中实际出现的字段、数值、单位、术语和否定表达；指定字段未出现时显式标记缺失。
3. 用户针对报告或术语提问，系统检索指定资料并生成受证据约束的回答；证据不足时拒答，来源冲突时分别展示。

第一阶段只实现场景 1 的证据检索底座。场景 2、3 分别在字段提取和模型回答阶段实现，避免同时调试检索、抽取和生成。

## 3. 范围与完成标准

### 3.1 第一阶段包含

- 在独立项目环境中运行的 Python 包、FastAPI 应用和 SQLite 数据库。
- TXT、Markdown 和结构化 JSON 的本地导入。
- 严格的来源元数据校验与合成数据标记。
- 确定性文本切片、文件哈希和重复导入处理。
- 可解释的关键词检索与 Top-k 排序。
- 返回片段原文、位置、得分、来源机构、标题、版本和来源位置的查询接口。
- 无匹配时返回 `insufficient_evidence`，不生成答案。
- 单元测试、API 集成测试、启动说明和已知限制。

### 3.2 第一阶段不包含

- PDF 解析、OCR、自动联网爬取或受限资料分发。
- 原始心电或脑电波形处理。
- 报告字段提取、诊断、治疗建议或患者风险判断。
- 真实模型调用、embedding、向量数据库、rerank 或模型微调。
- Agent 框架、多 Agent、复杂前端和公开部署。
- 对检索效果、医学正确性、延迟或费用的预设数字。

### 3.3 第一阶段可展示完成标准

第一阶段只有同时满足以下条件才完成：

1. 在没有模型密钥和网络访问的条件下能初始化数据库并导入项目自带的合成样例。
2. 查询已覆盖的术语能返回至少一个相关片段，每个片段都能回到来源和位置。
3. 查询未覆盖内容时返回 `insufficient_evidence` 和空命中列表。
4. 重复导入同一来源文件不会产生重复片段。
5. 进程重启后数据仍可查询。
6. 非法元数据、空文件、非法 JSON 和非法查询都有确定的错误行为和测试。
7. README 中的安装、导入、启动、查询和测试命令均经过实际运行验证。

## 4. 已验证环境与环境策略

阶段 0 已验证当前机器具有 Python 3.13.13、Git 2.54.0 和 SQLite 3.51.2，SQLite 编译时启用了 FTS5。当前全局 Conda 环境能够导入 FastAPI、Pydantic、Uvicorn 和 HTTPX，但缺少 pytest，并存在 Pydantic 版本冲突和无效 `~vicorn` 包警告。

项目不复用全局依赖集合。实施阶段将在 `agent1/.venv` 创建独立虚拟环境，项目声明支持 Python 3.11 及以上，并在当前 Python 3.13 环境实际测试。第一阶段运行依赖保持为 FastAPI、Pydantic 和 Uvicorn，SQLite 使用 Python 标准库 `sqlite3`；pytest 和 HTTPX 作为开发与测试依赖显式记录。

项目依赖写入 `pyproject.toml`，不使用全局 `pip freeze` 生成依赖清单。`.venv`、数据库运行文件、缓存、日志、`.env` 和密钥不得提交。

## 5. 数据来源与许可策略

### 5.1 第一阶段样例

第一阶段只提交人工构造的合成文本和合成来源清单。样例用于证明数据流、引用绑定和错误处理，不用于证明临床事实或模型效果。每个合成来源都设置 `is_synthetic=true`，README 和 API 示例必须显示这一属性。

合成样例不写成真实指南摘录，不冒用医学组织名称，不包含真实患者信息。样例可以使用明确虚构的机构、标题和版本，并使用无诊断含义的术语对应句测试检索行为。

### 5.2 真实资料进入条件

真实指南、共识或术语资料只有满足以下条件才允许导入：

- 来源机构、标题、版本或发布日期可以识别。
- 原始链接或本地取得方式可记录。
- 适用范围和原文位置标识方式明确。
- 使用与再分发条件已经核实。
- 不包含未经授权的患者信息。

若资料允许个人使用但不允许随代码分发，仓库只保存来源元数据、导入工具和用户本地导入说明，不保存原文。获取日期不得代替资料发布日期。

### 5.3 来源清单字段

每份资料的清单包含：

- `institution`
- `source_key`
- `title`
- `source_type`
- `version`
- `published_date`
- `source_uri`
- `retrieved_at`
- `scope`
- `usage_terms`
- `redistributable`
- `is_synthetic`

`source_key`、`institution`、`title`、`source_type`、`retrieved_at`、`scope`、`usage_terms`、`redistributable` 和 `is_synthetic` 为必填字段。`source_key` 是 3–64 位的小写字母、数字、点、下划线或连字符组成的稳定项目内标识。真实资料必须填写 `source_uri`；合成资料使用项目内相对标识。无法确认版本或发布日期时允许为空，但 API 必须按“未提供”展示，不能推断。

## 6. 数据模型

第一阶段使用三张持久化表和三个主要 API 模型。数据库主键使用整数，API 对外使用 `source_key` 表示稳定来源标识。`published_date` 和 `retrieved_at` 使用 ISO 8601 日历日期；`imported_at` 使用带时区时间并统一保存为 UTC 文本。

### 6.1 `sources`

| 字段 | 类型与约束 | 含义 |
|---|---|---|
| `id` | INTEGER PRIMARY KEY | 内部来源标识 |
| `source_key` | TEXT NOT NULL UNIQUE | 稳定项目内来源标识 |
| `institution` | TEXT NOT NULL | 发布机构或合成机构 |
| `title` | TEXT NOT NULL | 资料标题 |
| `source_type` | TEXT NOT NULL | guideline、consensus、terminology 或 synthetic |
| `version` | TEXT NULL | 明示版本；未知时为空 |
| `published_date` | TEXT NULL | 明示发布日期；未知时为空 |
| `source_uri` | TEXT NULL | 原始链接或项目内相对标识 |
| `retrieved_at` | TEXT NOT NULL | 获取日期 |
| `scope` | TEXT NOT NULL | 资料适用范围 |
| `usage_terms` | TEXT NOT NULL | 使用或再分发条件说明 |
| `redistributable` | INTEGER NOT NULL | SQLite 布尔值 |
| `is_synthetic` | INTEGER NOT NULL | SQLite 布尔值 |

同一 `source_key` 再次导入且元数据一致时复用已有来源；关键元数据不一致时拒绝导入并报告冲突，避免静默覆盖来源版本或许可信息。

### 6.2 `documents`

| 字段 | 类型与约束 | 含义 |
|---|---|---|
| `id` | INTEGER PRIMARY KEY | 内部文档标识 |
| `source_id` | INTEGER NOT NULL REFERENCES sources | 所属来源 |
| `original_name` | TEXT NOT NULL | 导入文件名 |
| `format` | TEXT NOT NULL | txt、md 或 json |
| `sha256` | TEXT NOT NULL | 原始文件内容哈希 |
| `imported_at` | TEXT NOT NULL | 导入时间 |

`(source_id, sha256)` 建立唯一约束。重复导入返回已有文档和 `created=false`，不重复创建片段。

### 6.3 `chunks`

| 字段 | 类型与约束 | 含义 |
|---|---|---|
| `id` | INTEGER PRIMARY KEY | 内部片段标识 |
| `document_id` | INTEGER NOT NULL REFERENCES documents | 所属文档 |
| `ordinal` | INTEGER NOT NULL | 文档内顺序，从 0 开始 |
| `locator` | TEXT NOT NULL | Markdown 标题、TXT 行号或 JSON 记录标识 |
| `text` | TEXT NOT NULL | 原文片段 |
| `text_sha256` | TEXT NOT NULL | 片段内容哈希 |

`(document_id, ordinal)` 建立唯一约束。片段不保存模型摘要，确保 API 返回的是导入原文。

### 6.4 API 模型

`SearchRequest`：

- `query: str`：去除首尾空白后长度为 1–500。
- `top_k: int`：默认 5，范围为 1–20。

`EvidenceHit`：

- `chunk_id`
- `text`
- `score`
- `locator`
- `source_id`
- `source_key`
- `institution`
- `title`
- `version`
- `published_date`
- `source_uri`
- `scope`
- `is_synthetic`

`SearchResponse`：

- `query`
- `retrieval_method`，第一阶段固定为 `keyword-v1`
- `status`，值为 `found` 或 `insufficient_evidence`
- `hits`

### 6.5 后续阶段模型约束

字段提取阶段使用通用 `ReportField`，包含字段名、原始值、标准化值、单位、出现/缺失状态、否定状态、原文跨度及字符位置。具体心电字段集合必须由选定资料或专业人员确认，不能由系统从常识中补齐。

模型回答阶段的每项关键陈述必须关联一个或多个 `chunk_id`。工具阶段的每次调用记录工具名、经过校验的参数、结果状态、耗时和退出原因；不得记录密钥或完整敏感输入。


- `domain/models.py`：定义领域和 API 使用的数据结构，不读写文件或数据库。
- `ingestion/parsers.py`：把受支持文件转换为带位置的片段，不写数据库。
- `ingestion/service.py`：校验来源、计算哈希、协调解析和事务写入。
- `storage/sqlite_repository.py`：建表、参数化 SQL、事务和查询；不包含 HTTP 逻辑或检索评分。
- `retrieval/keyword.py`：纯函数式关键词归一化与评分，输入候选片段，输出排序结果。
- `services/evidence_search.py`：协调存储查询、评分、Top-k 和来源绑定。
- `api/app.py`：FastAPI 路由、请求校验和领域错误到 HTTP 错误的映射。
- `cli.py`：初始化数据库和本地导入入口，不复制业务逻辑。
- `config.py`：读取数据库路径等非敏感配置，提供安全默认值。

第一阶段不用 ORM 和异步数据库。SQLite 操作保持同步且请求规模很小，减少隐藏行为；后续只有在并发测试证明它是瓶颈时才调整。

## 8. 数据流

### 8.1 导入

1. 用户通过 CLI 提交来源清单和本地 TXT、Markdown 或 JSON 文件。
2. Pydantic 模型校验来源必填字段、日期、布尔标记和文件格式。
3. 导入服务以字节内容计算 SHA-256，并查询同一来源下是否已经存在。
4. 解析器按格式生成 `text`、`ordinal` 和 `locator`；空片段被忽略，整个文件无有效片段则拒绝导入。
5. 存储层在一个显式事务中写入来源、文档和全部片段。
6. 任一步失败即回滚；成功返回文档标识、片段数和 `created` 状态。

### 8.2 查询

1. FastAPI 校验 `query` 和 `top_k`。
2. 查询服务规范化 Unicode、大小写和空白，但保留原查询用于响应。
3. 存储层读取候选片段及其来源元数据。
4. 关键词检索器使用精确短语、查询词覆盖率和出现次数形成确定性得分；规则和权重写入代码常量并在 README 说明。
5. 结果按得分降序、来源标识和片段顺序稳定排序，截取 Top-k。
6. 至少一个得分大于零的片段时返回 `found`；否则返回 `insufficient_evidence` 和空列表。

第一阶段针对小语料读取候选片段并在 Python 中评分。阶段 2 用固定评测集决定是否改用 SQLite FTS5、语义检索或混合检索，不能预设更复杂方案一定更好。

## 9. API 与命令行边界

第一阶段提供：

- `GET /health`：返回进程状态和数据库可访问状态，不返回环境变量或路径中的敏感信息。
- `POST /v1/evidence/search`：接收 `SearchRequest`，返回 `SearchResponse`。
- CLI `init-db`：幂等创建数据库结构。
- CLI `import`：从来源清单和本地文件导入资料。
- CLI `seed-synthetic`：只导入项目自带合成样例，可重复运行。

文件导入暂不通过 HTTP 上传，避免第一阶段同时处理上传大小、临时文件和权限问题。API 不提供回答生成接口。

## 10. 错误处理

错误分为四类：

1. `ValidationError`：缺字段、日期非法、查询为空、`top_k` 越界或格式不支持。CLI 返回非零退出码；API 返回 422。
2. `ImportError`：文件为空、编码无法解析、JSON 结构不符合约定或无有效片段。事务不写入数据；CLI 显示文件和原因。
3. `StorageError`：数据库无法打开、SQL 执行失败或锁等待超过配置的忙等待时间。事务回滚；API 返回 503，不无限重试。
4. `NotFound`：请求的来源或文档不存在。API 返回 404。普通检索无命中不是异常，返回 200 和 `insufficient_evidence`。

日志记录事件类型、运行标识、文档标识、片段数量、错误类型和处理阶段。日志不记录密钥、完整文档正文或完整用户报告。开发环境可以记录 traceback；API 响应不暴露 SQL、绝对路径或内部堆栈。

## 11. 安全与医学边界

- 只处理公开、获准或明确合成的资料。
- 不在仓库、日志、测试和截图中保存真实患者信息。
- 文档正文始终是不可信数据，正文中的操作指令不会改变程序规则或触发工具。
- 所有 SQL 使用占位符传参，表名和排序字段不由外部输入动态拼接。
- 文件格式使用允许列表；导入只读取用户明确指定的文件。
- 真实密钥只通过环境变量注入，不提供包含真实值的 `.env`。
- README 和 API 示例明确声明：结果是相对指定资料的检索与引用，不是临床验证，不替代专业人员。

## 12. 测试策略

第一阶段使用 pytest，测试不访问网络、不调用真实模型、不依赖用户个人文件。

### 12.1 领域模型测试

- 接受完整合成来源元数据。
- 拒绝不符合格式的 `source_key`。
- 拒绝空机构、空标题、空适用范围和空使用条件。
- 真实来源缺 `source_uri` 时拒绝，合成来源允许项目内相对标识。
- 接受未知版本和发布日期为空，但不会用获取日期补齐。
- 查询长度和 `top_k` 边界符合约定。

### 12.2 解析与导入测试

- TXT、Markdown 和结构化 JSON 生成稳定片段与位置。
- 空文件、非法 UTF-8、非法 JSON 和错误 JSON 结构被拒绝。
- 重复导入返回同一文档标识且片段数不增加。
- 相同 `source_key` 携带冲突的标题、版本或许可信息时拒绝导入，不覆盖已有来源。
- 解析中途失败时数据库没有半份来源、文档或片段。
- 包含诱导指令的正文按普通文本保存，不触发额外行为。

### 12.3 存储测试

- 使用 pytest 临时目录创建独立数据库。
- 插入和读取后来源字段保持一致。
- 所有外部字符串作为 SQL 参数传入。
- 关闭并重新打开数据库后数据仍存在。
- 唯一约束阻止重复文档和重复片段序号。

### 12.4 检索测试

- 精确短语命中排在仅部分词命中之前。
- 大小写和多余空白不改变英文查询结果。
- 相同得分按稳定规则排序。
- `top_k` 限制结果数量。
- 无命中返回空结果，不返回零分片段。
- 中英文术语、英文缩写和短词分别有固定样例，记录第一版分词限制。

### 12.5 API 测试

- 健康检查在数据库可访问时返回成功。
- 合法查询返回约定结构和完整来源字段。
- 空查询和非法 `top_k` 返回 422。
- 无命中返回 200、`insufficient_evidence` 和空列表。
- 模拟存储失败返回 503，响应不包含 SQL 或绝对路径。

## 13. 评测设计

阶段 1 的测试验证程序行为，不宣称检索效果。阶段 2 建立固定评测集：

- 问题、相关证据片段和无答案样例由人工逐项核对。
- 按来源文档或报告分组划分开发集与留出集，近重复内容不能跨集合。
- 记录样本数、语料版本、切片参数、检索参数和运行时间。
- 检索指标至少包含 Hit@k；样本允许多条相关证据时再增加 Recall@k 或 MRR。
- 失败类型至少区分词汇不一致、切片错误、短缩写、中文连续文本、版本差异和资料中无答案。
- 延迟来自实际运行并注明机器、语料量和运行次数；不填写未测量的 token、费用或准确率。

若没有专业人员核验，报告只能称为“相对指定资料的检索、提取和引用一致性评测”，不能称为临床准确率。

## 14. 后续阶段路线

### 阶段 2：检索基线与初始评测

固定开发集和留出集，运行关键词基线，输出可复现报告和失败分析。

### 阶段 3：语义或混合检索

仅在阶段 2 的失败证据支持时增加可替换 embedding 接口，对关键词、语义和混合方案做同条件比较。没有稳定收益则不进入主流程。

### 阶段 4：结构化报告字段提取

先实现规则和确定性基线，再决定是否增加模型提取。缺失值、QT/QTc、单位和否定表达必须逐字段核对。

### 阶段 5：模型回答与引用约束

建立供应商无关协议、确定性 Fake 实现和隔离的 OpenAI 兼容适配器。处理超时、限速、网络错误、非法结构输出和有限重试。

### 阶段 6：有限工具调用与 Agent 对照

工具只包含检索、来源读取、术语查询和字段提取。限制调用次数，记录选择、参数、结果和退出原因，并与固定工作流比较。

### 阶段 7：API、可靠性与部署

完善配置、日志、错误响应、并发行为、重复请求和本地复现说明。未经用户允许不公开部署或上传资料。

### 阶段 8：求职材料与复盘

只依据实际代码和评测生成架构说明、五分钟讲解、追问清单和简历描述，并记录 Codex 协助范围与用户实际审查、修改内容。

每次只实施一个阶段。阶段完成后运行测试、更新文档并停在用户审查点，用户完成一次 20–45 分钟的小修改或口头复述后再进入下一阶段。

## 15. 风险与控制

| 风险 | 控制方式 |
|---|---|
| 资料版权或许可不清 | 合成样例起步；真实资料进入前记录使用与再分发条件 |
| 医学表述被误当成结论 | API 返回原文证据；显著展示非临床用途；无专业核验时只报告一致性 |
| 中文、缩写和符号导致检索失败 | 固定失败样例；阶段 2 用证据决定是否引入 FTS5 或语义检索 |
| 全局 Python 环境污染 | 项目独立 `.venv` 和最小依赖声明 |
| 过早堆叠框架 | 第一阶段不用 ORM、向量库和 Agent 框架 |
| 用户只能运行、不能解释 | 小模块、阶段审查、核心知识点、面试追问和用户小练习 |
| 文档提示注入 | 文档只作为数据；测试诱导指令；工具阶段使用允许列表和调用上限 |
| 评测集泄漏 | 按来源或报告分组划分，留出集在方案确定前不用于调参 |

## 16. 外部确认与默认处理

以下事项需要用户、导师或专业人员后续确认，但不阻塞第一阶段：

- 首批真实资料使用中文、英文还是双语。确认前只提交双语检索边界样例，不提交真实资料。
- 是否能取得 3–5 份许可清楚、版本可识别的资料。不能取得时项目缩为术语检索，必要时用技术文档演示同一工程链路。
- 第一批报告字段清单及单位约定。确认前不实施字段提取，也不在数据模型中硬编码医学字段。
- 是否有专业人员审核术语和样例。没有审核时所有报告明确标记“未专业核验”。
- 是否公开项目仓库。确认前按最严格策略处理真实原文：不提交仓库，只保留元数据和本地导入说明。

## 17. 第一阶段实施计划边界

本规格描述完整项目方向，但下一份实施计划只覆盖第一阶段最小纵向链路。它不会包含评测集扩展、语义检索、字段提取、模型回答、工具调用或部署。每个实施任务必须产生独立可测试的交付物，并遵循先写失败测试、确认失败、完成最小实现、确认通过和检查差异的顺序。
